
## Grouping

The finding that settles it: of 159 distinct MolLib-pipeline molecules, **only 7 appear in more than one topic** — water, CO₂, N₂, methane, ammonia (all already in `mol-solvation.js`/`mol-small.js`), plus chlorophyll a and the cellulose microfibril. The duplication problem that would force a different scheme basically doesn't exist.

So group **by topic, which is the lesson axis** — that's what the existing rule already demands ("a page loads only the molecules it shows"), and it's why today's files are named `solvation`/`monomers`/`glycolysis`/`contrast` rather than `sugars`/`acids`. The catalog's 24 topics run 1–22 molecules, median 5; today's files hold 2–14. Same granularity. Merging the runt topics up to their Unit gives roughly:

| file | from | \~specs |
| --- | --- | --- |
| `mol-solvation` / `mol-small` | existing + Water & inorganics | 12 |
| `mol-carbs` | Unit 1 Carbohydrates | 15 |
| `mol-lipids` | Unit 1 Lipids + Membrane | 16 |
| `mol-aminoacids` | Unit 1 Proteins (the 22 monomers) | 22 |
| `mol-nucleic` | Unit 1 Nucleic acids + Chromatin + Regulation | 11 |
| `mol-carriers` | Unit 3 Energy carriers | 13 |

| `mol-krebs`, `mol-photosynthesis`, `mol-etc` | Unit 3 | 9 / 6 / 3 |

\~12 files. The 99 PDB rows are a separate pipeline and don't belong in any of them.

## Storage

**The database already exists** — `tools/sdf/` holds the committed PubChem records, and this CSV is the index. The real question is whether the *derived* specs stay as JS, and the answer splits along a line the repo already draws: **fidelity tier**.

* **Tier 2/3 — contrast pairs, subjects, skel twins: stay hand-written.** Their comments are load-bearing. `MolecularGeometry.md` §1.6 *requires* a schematic to be declared in a comment, and a skel-built spec isn't data at all — it's code, and the construction is the provenance. A database would strip exactly the part that makes them trustworthy.

* **Tier 1 — bulk PubChem props: generate the file.** There's a precedent, and it's not a new idea here: `residues.js` is generated by `tools/bake-residues.js`, carries *"Do not edit: re-run the baker"*, and `check-residues.js` re-bakes and fails if it's stale. Same for `folding/data/*.bin`. Roughly 100 of the 154 PubChem rows have no per-molecule reasoning to preserve — they're coordinates plus a provenance block, which is precisely what a baker should emit.

That keeps the no-build, classic-script contract intact (a generated `.js` still loads as a plain script; a runtime JSON fetch would change the page contract), and it means an agent adding a tier-1 molecule edits *the catalog row*, not the library.

At \~45 lines/spec today, 166 hand-written specs would be \~7,500 lines. The generated-vs-authored split is what stops that number being the bad kind.
